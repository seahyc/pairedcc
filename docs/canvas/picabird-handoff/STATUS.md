## Decisions
- **2026-11-17 Rules and UGC:** YC removed the "records contain source facts only / an LLM never writes record content" rule from AGENTS.md (YC didn't write it; it doesn't fit the shopping site). Owner feedback comes from websites and forums other than Reddit; third-party test results (Tom's Guide, YouTube, etc.) are in scope. Still label model-written summaries and link their sources.
- **2026-11-17 Electronics scope:** YC: cover consumer electronics (main focus) and components, for US, tech-forward, AI-native shoppers. Aim to be the most agent-friendly, SEO and AEO-leading site per electronics category: support every agent format (HTML, JSON-LD, .md, .json, llms.txt, poppy.json, OpenAPI, MCP). YC's hypothesis: organised forum/UGC feedback is valuable to agents. Site plan: `research/notes/2026-11-17-electronics-site-plan.md` (proposal). UGC sourcing: websites and non-Reddit forums (see Rules and UGC).
- **2026-11-17 Focus:** YC: focus on the agent shopping layer, electronics first; the thinking canvas goes to another agent. Distribution must not depend on approved Muse/Grok connectors, so prioritise web pages and `/.well-known/poppy.json` (Muse checks it first on every site) over MCP alone.
- **2026-11-17 Canvas foundation:** YC authorised getting the canvas running and feeling smooth first, referencing the open Paper file. Local prototype uses tldraw 5.6.1 with a Paper-inspired shell. This does not choose the eventual HTML/widget runtime. No deployment or license purchase.
- **2026-11-17 Canvas agent access:** Both a built-in assistant and external agents are day-one requirements. Collaborative specification continues before implementation; research/data-first scope remains a proposal. Existing implementation preserved.
- **2026-11-06 Market-selection criterion:** YC wants to iterate into a large existing market (contact intelligence/ZoomInfo analogy) or a fast-growing one (shopping through Muse/Grok). Reopen shopping market research; the official-records scenario is not a ceiling on the business. No new vertical selected and no product/deployment change authorized by this decision.
- **2026-11-04 Direction:** live-data API for agents, sold to enterprise; consumers can use the same API (the exa.ai model). Why: a shopping catalog API has no clean buyer (Gemini chat in `research/private/sources/`). The shopping thesis's later stages (verified outcomes, guarantees, take-rate) were not disproven, only parked.
- **2026-11-04 Name:** Picabird; picabird.ai registered (Cloudflare, expires 2028-11-04, US$160 + GST = S$228.24).
- **2026-11-04 Page:** all six use cases weighted equally (power grid, court dockets, municipal land use, customs/trade, life sciences, shopping). For shopping, lead with procurement agents. Hybrid look. CTA is a form → Worker + D1. Show the value live with real data, like Exa.
- **2026-11-04 Format:** compact typed records with field-level provenance; the LLM only interprets queries; summaries are deterministic; notices are kept separate from warnings; watches with diffs are the moat (`notes/2026-11-04-agent-data-format.md`).
- **2026-11-04 Grid sources:** ERCOT's sites are geo-blocked, so ERCOT is early access. MISO's open JSON queue is technically reachable, but its terms forbid "automated means … agents, robots, scripts", so the adapter is off (`ENABLE_MISO`) until MISO gives permission. The live grid example uses FERC documents via the Federal Register API.
- **2026-11-04 Hosting:** personal Cloudflare account, free tier only for now.
